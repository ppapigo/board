# 아키텍처

## 구조

```text
Browser / Front-end
  ├─ Authorization: Bearer <JWT>
  ├─ HttpOnly refreshToken cookie
  └─ JSON 또는 multipart/form-data
            ↓
Spring Security Filter Chain
  └─ JwtAuthenticationFilter
            ↓
Controller → Service → Repository → MySQL
                 ├─ domain event → NotificationEventListener
                 └─ FileStorageService → ./uploads
                                      ↘ /images/**
```

## 패키지 책임

| 패키지 | 책임 |
|---|---|
| `auth` | 로컬 인증, JWT, refresh token, OAuth/OIDC |
| `board` | 게시판 관리 |
| `post` | 게시글 CRUD와 파일 저장 |
| `comment` | 댓글/답글과 소프트 삭제 |
| `reaction` | 게시글 반응 토글과 집계 |
| `notification` | 댓글 이벤트 기반 알림 |
| `user` | 사용자 프로필 조회 |
| `global.entity` | JPA 엔티티 |
| `global.config` | Security, MVC, 정적 리소스 설정 |
| `global.exception` | 공통 오류 코드와 응답 |

## 요청과 데이터 규칙

- API 기본 주소(로컬): `http://localhost:8090`
- JSON 필드명은 기본 Jackson camelCase다. 예외는 회원가입의 `nick_name`이다.
- 페이지 응답은 Spring Data `Page`의 DTO 직렬화 형식이다. 공통적으로 `content`, `page.number`, `page.size`, `page.totalElements`, `page.totalPages`를 사용할 것으로 예상되나 실제 응답 샘플을 고정해야 한다.
- 날짜는 `LocalDateTime` 또는 `toString()` 결과이며 타임존 오프셋이 없는 ISO-8601 형태다.
- 업로드 파일은 `./uploads`에 UUID 기반 이름으로 저장되고 `/images/{storedName}`으로 노출된다.
- 댓글 생성은 트랜잭션 커밋 후 알림 이벤트를 처리한다. 알림 실패는 원 댓글 요청을 실패시키지 않는다.

## 저장소 관계 요약

자세한 필드는 [[03-도메인-모델]]을 본다.

```text
User 1─1 UserProfile
User 1─N Post N─1 Board
Post 1─N PostImage
Post 1─N Comment
Comment 1─N Comment (root → reply, 한 단계만 허용)
User N─M Post (through PostReaction)
User 1─N Notification (recipient / actor)
User 1─1 RefreshToken
```

## 설계 특성

- 세션 비저장(stateless) JWT 인증이다.
- 읽기 API는 대부분 공개이고 쓰기 API는 인증을 요구한다.
- 작성자 권한은 `@PreAuthorize`와 별도 security bean에서 확인한다.
- JPA 스키마는 `ddl-auto: update`로 자동 변경된다. 운영 마이그레이션 전략은 아직 없다.
- 파일과 DB 저장은 단일 트랜잭션이 아니며 생성 실패 시 저장 파일을 보상 삭제한다.
