# 도메인 모델

## 엔티티

| 엔티티 | 핵심 필드 | 규칙 |
|---|---|---|
| `User` | email, password, nickName, provider, providerId, profileImageUrl, role | email unique, role `USER/ADMIN` |
| `UserProfile` | user, phoneNumber, birth | User와 1:1, 회원가입 때 생성 |
| `Board` | name, description, createdAt, updatedAt | 이름 중복을 서비스에서 검사 |
| `Post` | title, body, board, author, viewCount, timestamps | 제목 5~200자, 본문 필수 |
| `PostImage` | storedName, originalName, contentType, size, sortOrder | 게시글별 정렬, cascade 삭제 |
| `Comment` | post, user, parent, content, deleted, createdAt | 내용 최대 100자, 루트/답글 1단계, 소프트 삭제 |
| `PostReaction` | post, user, type | 사용자·게시글 조합당 한 반응 의도 |
| `CommentReaction` | comment, user, type | 사용자·댓글 조합당 한 반응 |
| `Notification` | recipient, actor, type, postId, commentId, read | 타입은 댓글/답글 |
| `RefreshToken` | userId, token, expiresAt | 사용자당 하나, token unique |

## 핵심 비즈니스 규칙

### 게시글

- 작성에는 유효한 게시판과 인증 사용자가 필요하다.
- 생성 시 이미지는 선택이며 최대 5개다.
- 허용 MIME/확장자: jpg, jpeg, png, gif, webp.
- 파일 하나 최대 2MB, 요청 전체 최대 20MB다.
- 상세 조회에서 로그인한 비작성자만 조회수가 증가한다. 비회원 조회는 증가하지 않는다.
- 수정은 제목/본문만 가능하고 이미지 변경 계약은 없다.

### 댓글

- `parentId = null`이면 루트 댓글, 값이 있으면 답글이다.
- 다른 게시글의 댓글을 부모로 지정할 수 없다.
- 답글에 다시 답글을 달 수 없으며 삭제된 댓글에도 답글을 달 수 없다.
- 삭제는 행 삭제가 아니라 `deleted = true`다.
- 루트 댓글 목록은 최신순 페이지이며 자식은 오래된 순으로 포함하려는 구조다.

### 반응

- 가능한 값은 `LIKE`, `DISLIKE`다.
- 같은 값을 다시 전송하면 반응을 취소한다.
- 다른 값을 전송하면 타입을 변경한다.
- 응답은 최신 좋아요 수, 싫어요 수, 내 반응을 반환한다.
- 게시글과 댓글에 동일한 토글 규칙을 적용한다.

### 알림

- 게시글에 루트 댓글이 달리면 게시글 작성자에게 `COMMENT_ON_POST` 알림을 만든다.
- 루트 댓글에 답글이 달리면 댓글 작성자에게 `REPLY_ON_COMMENT` 알림을 만든다.
- 자기 자신의 활동에는 알림을 만들지 않는 것이 의도이나 현재 리스너 구현을 재검토해야 한다.
- 수신자만 자신의 알림을 읽음 처리할 수 있다.

## 프런트엔드용 열거형

```ts
type UserRole = 'USER' | 'ADMIN';
type ReactionType = 'LIKE' | 'DISLIKE';
type NotificationType = 'COMMENT_ON_POST' | 'REPLY_ON_COMMENT';
```

> [!important]
> API DTO와 엔티티는 동일하지 않다. 프런트엔드는 엔티티 구조를 추론하지 말고 [[05-API-레퍼런스]]의 응답만 사용한다.
