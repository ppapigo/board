# 결정사항과 알려진 이슈

코드 분석으로 확인한 항목이다. `P0`는 프런트엔드 본개발 전에, `P1`은 MVP 완성 전에 해결 또는 계약 확정이 필요하다.

## P0 — 계약·보안

| 항목 | 현재 상태 | 권장 결정 |
|---|---|---|
| 공개 role 승격 | signup body의 `role="ADMIN"`으로 관리자 생성 가능 | 서버에서 항상 USER로 강제하고 관리자 생성은 별도 보호 기능으로 분리 |
| 비밀값/DB 설정 | JWT secret과 DB 암호가 `application.yaml`에 존재 | 환경 변수로 이동하고 노출된 secret은 교체 |
| CORS | 별도 CORS 허용 설정 없음 | 배포 프런트 origin allowlist와 credentials 정책 확정 |
| OAuth 완료 | 두 OAuth 구현이 공존하며 성공 시 JSON 직접 반환 | 한 방식으로 통일하고 프런트 callback/일회용 code 교환 계약 정의 |
| 댓글 트리 | 변환 코드는 children을 만들지만 DTO에는 children 없음 | `children: CommentResponse[]` 또는 별도 답글 endpoint 중 하나 확정 |
| 사용자 역할 응답 | `UserResponse.role` 필드가 있으나 로그인에서 설정하지 않음 | role을 항상 반환하거나 `/me` 인증 identity 응답 확장 |

## P1 — API 일관성·기능 결함 위험

| 항목 | 관찰 | 영향/제안 |
|---|---|---|
| access token 형식 | 로그인은 `Bearer ` 포함, 재발급은 미포함 | raw JWT로 통일 권장 |
| refresh token 노출 | HttpOnly cookie와 body에 동시에 반환 | production body에서 제거 |
| 상세 조회수 | 로그인 비작성자만 증가, 비회원은 증가하지 않음 | 제품 규칙 확정 후 서버 수정 |
| 게시글 목록 DTO | 상세 외 응답에서 like/dislike null, 권한 false | 목록 전용 DTO를 쓰거나 필드 계약 통일 |
| 댓글 변환 | `Comment.toResponse` 생성자 인자와 DTO 의미가 불일치하는 흔적 | 직렬화 테스트와 함께 수정 |
| 알림 자기 제외 | recipient가 actor와 같아도 return하지 않고 create를 시도 | 명시적으로 return하여 자기 알림 차단 |
| 알림 오류 코드 | 없는 알림 읽기에 `COMMENT_NOT_FOUND` 사용 | `NOTIFICATION_NOT_FOUND` 추가 |
| 알림 enum 저장 | `@Enumerated`에 STRING 미지정 | `EnumType.STRING`으로 데이터 안정성 확보 |
| 알림 정렬 | 기본 오래된 순 | 최신순을 기본으로 할지 결정 |
| 게시판 update 검증 | `@Valid` 없음 | 생성과 동일한 validation 적용 |
| 이미지 수정 | 게시글 update가 JSON 제목/본문만 받음 | 이미지 유지/추가/삭제/정렬 계약 추가 |
| 페이지 schema | Spring DTO 모드 의존, 샘플/명세 없음 | 통합 테스트로 JSON shape 고정 |
| 날짜/시간 | offset 없는 문자열 | UTC+offset 또는 명시적 KST 정책으로 통일 |
| 오류 문자 | 여러 Java 주석/메시지가 인코딩 손상 상태 | 소스 UTF-8 복원, 사용자 메시지 검증 |

## P2 — 유지보수

- API 명명 규칙이 단수형과 동사 suffix(`/new`, `/all`, `/update`)를 혼용한다. 차기 버전에서 RESTful 복수 리소스 경로를 고려한다.
- `PostListResponse`, `BoardDTO`, `RefreshTokenRequest`, 댓글 반응 기능 등 미사용/미완성 코드를 정리한다.
- DB schema migration 도구(Flyway/Liquibase)를 도입하고 `ddl-auto` 운영 사용을 중단한다.
- 업로드 파일의 magic-byte 검사, orphan 정리, 외부 object storage 전략을 추가한다.
- 현재 자동 테스트는 context load 수준이다. [[06-개발-가이드]]의 회귀 테스트를 추가한다.
